# 雨停之前 · After Rain

我围绕“雨夜咖啡馆里的一次相遇”，完成了这个移动端优先的单角色互动场景。26 岁的旅行摄影师 Mira 正在等待一位旅伴，体验者可以通过文字或语音与她交流，并触发表情、镜头和照片事件。

开发过程中，我使用 Codex 辅助搭建和实现，把主要精力放在需求取舍、代码审查、自测和体验调整上。下面记录的是我实际推动的优化，以及当前实现的边界。

## 我做的主要优化

1. **让人物和场景更有临场感。** 我认为初版扁平 SVG 的人物与背景不够吸引人，因此提出改成电影感的写实方向。我反复调整人物外观、眼神、肤质、灯光和构图，并让字幕与输入区退到底部，给人物面部留出空间。写实素材由 AI 辅助生成，我通过实际预览和使用来判断效果。
2. **让雨滴真正像落在窗外。** 先后指出雨滴像浮在室内、速度过慢、缺少错落感，以及左侧窗格看不到滑落等问题。我让 Codex 排查遮挡和绘制逻辑，再逐轮调整水珠的尺寸、数量、速度、起滑间隔和水痕；最后对左侧窗格单独调整尺寸，而不是让所有窗格使用完全相同的参数。
3. **让声音贴合人物，并能随项目复现。** 多次反馈声音机械、僵硬或与人物形象不匹配，要求更清澈婉转、语速有自然顿挫。角色音色最终统一为 Maia，Mock 与 Live 采用同一音色方案，并将音色档案、参考音频和 22 句预制录音保存在项目中，减少设备默认 TTS 带来的差异。
4. **提高真实对话的针对性。** 在体验中关注不同问题是否得到有针对性的回应，明确区分了固定脚本的 Mock 和实时生成的 Live。随后我选择将真实对话升级为 `qwen3.7-plus`，并要求提示词优先回应当前问题、自然使用已知姓名和偏好、减少重复，也避免把无关话题强行拉回雨、咖啡或照片。
5. **增加有层次的咖啡馆声音。** 选择了柔和电钢琴作为低音量配乐，并要求客人进出时的风铃稍微突出。经过几轮试听，我选定日式 Fūrin 素材，要求将它整理成约两秒、轻碰两三下的效果；当前版本是 2.1 秒、三次轻碰。氛围音单独控制，Mira 说话时压低音乐，录音时静音，避免环境音干扰交流。
6. **补齐可维护性和提交前检查。** 在效果调整后，我又安排了代码审查与回归检查，要求整理换行、空行和必要注释，并清理废弃素材、旧录音及调试产物。Codex 辅助修复了录音竞态、资源释放、图片加载超时和端口占用误报等问题；我将这些技术检查与自己的体验确认分别记录在 [AI_USAGE.md](AI_USAGE.md) 中。

## 本地启动

前置条件：Node.js 22.12+、npm、首次安装可联网。当前开发环境为 Node.js 22.23.1。

在项目根目录执行：

```sh
npm run demo
```

脚本自动运行 `npm ci`、生产构建并启动 Mock 服务，默认打开 [http://localhost:3001](http://localhost:3001)。不需要 `.env` 或模型密钥；已有 `PORT` 配置时以该配置为准。`Ctrl+C` 退出。Mock 故障演示入口会自动开启。

日常开发及检查：

```sh
npm ci
npm run dev
npm run typecheck
npm run lint
npm run build
npm start
```

`npm run format` 格式化源码。生产入口为 `dist/server/index.js`，静态页面位于 `dist/client`。Node 服务需要整个项目目录中的 `server/fixtures`，不能只复制 `dist` 后丢弃 Mock 音频。

端口通过 `PORT` 配置，默认 3001。若端口已被占用，停止旧进程或配置其他端口；程序会报告监听失败并退出。手机真实麦克风需要可信 HTTPS；桌面本机 `localhost` 可以录音。手机访问电脑的普通局域网 HTTP 地址不等同于 localhost。

## 两种模式

### Mock

- 11 类话题分支根据输入文本及当前剧情选择，包含等待原因、旅行、咖啡、照片、雨窗和告别。
- 22 句中文回复配套本地 WAV，另有一条示例用户录音。无需运行时系统语音或外部模型网络。
- 可以实际录制麦克风并验证开始、停止和打断；Mock 的转写是明确标识的预设结果，不识别录音语义。
- “示例语音”使用本地录音经过 multipart 上传和相同的服务端处理路径，不调用真实 STT。
- 左上场景、当前句字幕及底部交互始终是主界面，不展示聊天消息列表。

### Live

Live 的对话、识别、合成已统一使用阿里云百炼，不依赖 OpenAI 或 DeepSeek 密钥。

尚无 `.env` 时复制 `.env.example`；已有 `.env` 时保留原文件并补充模板中的 `DASHSCOPE_*` 配置，避免覆盖已有私密配置。填写与北京地域对应的百炼 API Key 后重启：

```sh
npm run dev
```

| 配置                         | 用途                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| `APP_MODE`                   | 默认 `mock`；设为 `live` 时配置不完整会启动失败                       |
| `PORT`                       | 默认 3001                                                             |
| `DASHSCOPE_API_KEY`          | 百炼密钥，三段调用共用，仅保存在服务端                                |
| `DASHSCOPE_BASE_URL`         | 默认 `https://dashscope.aliyuncs.com`；只填 HTTPS 域名，不带 API 路径 |
| `DASHSCOPE_LLM_MODEL`        | 默认 `qwen3.7-plus`，关闭思考模式，使用 JSON 输出                     |
| `DASHSCOPE_ASR_MODEL`        | 默认 `qwen3-asr-flash`，HTTP 同步识别短录音                           |
| `DASHSCOPE_TTS_MODEL`        | 默认 `qwen3-tts-flash`，取自 `server/voice-profile.json`              |
| `DASHSCOPE_TTS_VOICE`        | 默认 `Maia`；环境变量可覆盖项目音色档案                               |
| `DASHSCOPE_TTS_INSTRUCTIONS` | 仅在显式使用可用的 Instruct 模型时生效；当前普通 Flash 不发送此参数   |
| `ENABLE_DEMO_FAULTS`         | 默认 false；只对 Mock 会话允许有限故障注入                            |

填写 `DASHSCOPE_API_KEY` 后，模式菜单会开放“真实对话”；也可设置 `APP_MODE=live` 默认进入真实模式。切换模式会创建新会话，刷新页面后使用服务端默认模式。当前项目已完成真实百炼调用验证；换用其他账号或地域时仍需核对模型权限、额度和网络。Mock 的台词与转写保持预设，不因更换 Live 模型而改变。

获取密钥见[百炼 API Key 文档](https://help.aliyun.com/zh/model-studio/get-api-key)。新加坡地域使用 `https://dashscope-intl.aliyuncs.com` 和对应地域的密钥；也支持北京、新加坡的业务空间专属域名。当前适配的 ASR 接口不覆盖美国地域。

Live 使用 Node.js 原生 `fetch`，适配器为 `server/providers/bailian.ts`：

1. 识别：录音以 Base64 Data URL 发送至 `/compatible-mode/v1/chat/completions`，使用 `input_audio` 和 `asr_options`。[ASR 文档](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)
2. 对话：同一兼容接口，设置 `response_format=json_object`，提示词包含完整场景 JSON Schema；返回后用 Zod 及剧情规则再次校验。[Chat API 文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)
3. 合成：调用 `/api/v1/services/aigc/multimodal-generation/generation`。Instruct 模型通过 `parameters.instructions` 和 `optimize_instructions` 接收表达指导，与官方 Python SDK 序列化保持一致。普通 Flash 模型不发送指令参数。[Qwen-TTS 文档](https://help.aliyun.com/zh/model-studio/qwen-tts-api)

TTS 返回的临时音频由后端立即下载，限制为百炼结果 OSS 域名并使用 HTTPS；下载不携带 API Key，不跟随重定向。校验 WAV 后纳入现有会话音频仓库；内联 PCM 转换为 24 kHz WAV。下载与读取沿用当前轮取消信号，未完成的旧轮不会重新播放。

## 系统结构

| 目录/模块                       | 职责                                                     |
| ------------------------------- | -------------------------------------------------------- |
| `src/components`                | 写实场景、角色表情、雨滴、字幕、输入及恢复提示           |
| `src/lib/session-controller.ts` | 当前轮所有权、取消、录音与播放协调                       |
| `src/lib/audio-player.ts`       | 单播放器、句队列、加载/自动播放失败、阅读降级            |
| `src/lib/ambient-audio.ts`      | 配乐与风铃、独立音量、对话压低、录音静音及后台暂停       |
| `src/lib/scene-assets.ts`       | 图片预加载、超时、取消与失败收敛                         |
| `src/lib/recorder.ts`           | 授权、格式探测、按住录制、音轨生命周期                   |
| `src/lib/scene-director.ts`     | 有效轮次的场景事件与去重                                 |
| `shared`                        | TypeScript 契约与 Zod 运行时验证                         |
| `server/routes.ts`              | 同源会话 API、文本/音频输入、回执和音频访问              |
| `server/turn-service.ts`        | STT/LLM/TTS 调度、阶段超时、有限并发与降级               |
| `server/session-store.ts`       | 会话归属、轮次序号、回执、已呈现历史与剧情事实           |
| `server/audio-store.ts`         | 最多 64 MiB 的临时内存音频，10 分钟过期，取消即清理      |
| `server/providers`              | Mock 与 Live 的同一业务接口                              |
| `server/fixtures`               | Mock 台词和配套本地音频                                  |
| `server/voice-profile.json`     | Maia 音色、表达目标与参考音频信息                        |
| `public/assets`                 | 写实 WebP 场景与表情素材、灯塔照片、配乐、风铃和来源清单 |

会话空闲 30 分钟过期，全局最多 100 个会话，每个浏览器归属最多 4 个；超过归属上限释放最旧会话。没有数据库，进程重启后需要重新进入场景。音频通过 Cookie 验证所属会话，不直接暴露静态临时文件。

## 语音与打断

我选择按住说话，是为了在短期 MVP 内把输入边界和取消一致性做稳，避免同时引入 VAD、附和判断及回声误打断的额外变量。

1. 首次“启用麦克风”单独请求授权。后续按住录制，松开发送；可以使用聚焦按钮后的空格键。
2. 浏览器探测 WebM/Opus、WebM、MP4 的支持情况。录音最长 30 秒、最大 5 MiB；短于 300ms 的录音不提交。
3. 新意图开始时递增 `turnSeq`，先本地暂停声音、移除监听和未播放队列，再发起取消/新请求。
4. 后端取消所有更小序号的工作，并维持 `minAcceptedSeq`。即使取消请求迟到，也不能取消同序号的新轮。
5. 每次异步返回和媒体回调检查 `sessionId`、`turnId`、`turnSeq`。取消网络只是资源优化，身份校验才是迟到响应隔离的最后屏障。
6. 播放器的 `playing` 事件驱动 speaking 和本句字幕；`ended` 才提交完整播出的句子。未播放句子不记入已说出历史。
7. 发生音频故障时用户可以逐句阅读，阅读回执与已播放回执分开。自动播放被拒绝时显示“点击播放”。
8. 页面隐藏、重新开始、切模式或卸载会停止音轨、声音和瞬态动作。重新显示时不自动续播旧轮。

STT、LLM、单句 TTS 的超时分别为 15、20、15 秒；整轮上限 45 秒。百炼请求不自动重试，避免取消后产生隐蔽的新调用。TTS 每批最多并发两句，全部准备后返回；当前不是流式语音方案。

## 角色与场景协议

Provider 返回 1–3 段结构化回复。每段包含文本、`neutral/curious/warm` 情绪、`none/look_window/show_photo` 动作，以及允许的场景事件。

| 事件     | 执行时机   | 作用                                                     |
| -------- | ---------- | -------------------------------------------------------- |
| `camera` | 当前句开始 | `table` 或 `window` 镜头构图                             |
| `photo`  | 当前句开始 | 显示或收起唯一白名单资源 `lighthouse_photo`              |
| `story`  | 当前句结束 | 更新 `arrival/conversation/photo_revealed/farewell` 节点 |

模型不生成轮次 ID、资源 URL、HTML、CSS 或 JavaScript。服务端在 Schema 与业务转移验证后分配事件 ID。播放回执幂等合并；场景字段按服务端登记的轮次和事件顺序更新，迟到旧事件不能覆盖新状态。[百炼结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

当前角色使用同一人物的写实素材、表情帧和 CSS 动画，呈现待机、倾听、思考和说话状态；望向窗外与展示照片是两种非说话视觉状态。灯塔照片和雨窗镜头由当前回复触发，眨眼、呼吸和 Canvas 雨滴作为环境动画持续运行。视觉素材预先生成，运行时不调用图片或视频生成服务。

## 氛围音与声音取舍

我希望环境音增强咖啡馆的空间感，同时把对话始终放在前面。因此配乐与风铃使用独立于角色语音的 Web Audio 声道：

- 点击“走进咖啡馆”后，声音资源与会话就绪时播放一次进门风铃，随后在空闲时错落播放风铃。
- Mira 说话时，音乐降低到平时的 18%；等待回应时保持较低音量。
- 等待麦克风授权、录音和倾听时立即静音；已经响起的风铃也会停止。
- 切到后台时暂停；关闭后，迟到的资源加载不会重新开声。
- 右上扬声器开关与模式菜单中的音量滑块只影响氛围音，不改变 Maia 的对白音量。

目前配乐为约 53 秒的原创电钢琴循环。风铃基于 ayustat2001 的 [Furin japanese wind chime.wav](https://freesound.org/people/ayustat2001/sounds/501168/)（CC0），按我的选择剪辑和重排为 2.1 秒的三次轻碰，并做淡出与响度校准；不是从某部动画截取的原声。音频已随项目保存，素材来源、处理方式和校验值见 `public/assets/manifest.json`。重新生成氛围音使用 `scripts/generate-ambience.mjs`，需要 FFmpeg；直接运行应用不需要安装 FFmpeg。

## 关键技术选择与取舍

我优先完成稳定的单角色闭环，保留 HTTP 请求、句级字幕、有限的结构化场景指令和内存会话。这样可以明确控制每轮回复、媒体和取消边界，也能用 Mock 重复演示故障与恢复。代价是回复需要先生成再合成，尚未实现边生成边播放，也没有长期记忆和跨进程会话恢复。

对话模型升级后，我先保持非思考模式，兼顾回答质量和语音等待时间；是否引入流式传输或更复杂推理，会以实际延迟和对话效果为依据。视觉上，我选择预制写实素材结合状态动画，控制加载成本与角色一致性，没有把实时生成视频或精确口型作为本次 MVP 的必需项。

## 故障演示

`npm run demo` 开启故障控制。进入场景后打开右上“演示模式”，选择一次故障，再发送话题：

- 语音不可用：显示文字阅读入口，允许后续正常输入。
- 延迟 8 秒：在返回前发送新问题或打断，旧轮不得回到界面。
- 回应超时：显示错误及重试入口。

普通 `npm run dev` 默认不开启故障控制；可在本地 `.env` 设置 `ENABLE_DEMO_FAULTS=true`。Live 会话拒绝故障参数。

## 素材、服务与投入

- 视觉：我确定写实方向并多轮调整，使用内置 `image_gen` 辅助生成原创成年角色、场景、表情和灯塔照片；来源及提示词记录在 `public/assets/manifest.json`。
- 角色声音：当前为百炼 `qwen3-tts-flash` 的 `Maia`。22 句 Mock 回复预生成 24 kHz WAV；Live 按相同音色档案生成新回复。参考音频保存在 `server/fixtures/mira-reference.wav`。早期使用过 macOS Tingting 和晓伊，示例输入及旧演示视频保留各自的历史音频。
- 重新生成角色声音运行 `node scripts/generate-mock-audio.mjs`：配置本地百炼密钥后，脚本复用 Live 适配器与项目音色；全部生成成功后才替换素材并更新来源。当前普通 Flash 模型不使用表达指令参数。
- 氛围声：电钢琴由项目脚本原创合成，日式风铃来自上述 CC0 录音；处理后的 MP3 和用于再生成的风铃源片段均随项目保存。
- Live：百炼 `qwen3.7-plus` 对话、`qwen3-asr-flash` 识别、`qwen3-tts-flash` 合成，依赖对应地域的密钥、模型权限和额度。
- 工程：React、Vite、Express、Zod、Multer；云端请求使用 Node.js 原生 fetch；全部版本由 `package-lock.json` 锁定。没有远程字体依赖。
- 我在 2026-10-25 至 2026-10-26 期间分阶段完成开发，结合 AI 辅助实现、我自己的代码审查、自测和后续调整，实际投入约 6 小时。初版自动搭建约 40 分钟只是其中一个阶段；原计划的 36 小时是实施估计，不作为实际工时。
